# 生命场原生桌面应用：方案与边界

## 1. 目标与第一版范围

在 Kubuntu / KDE 上，将生命场、日期时间、运行代数和常用系统控制集成为一个原生应用，避免网页壁纸宿主额外缩放与销毁网页造成的问题。网页版本继续保留，本实验放在同仓库 native/，不替换在线版。

仅以 **1920×1080、2560×1440 物理像素**为目标。生命场为 256×180、占左侧 80%；细胞分别为 6×6、8×8 物理像素。其余宽度作为右侧控制区。其他尺寸只提供居中的整数倍预览，不承诺铺满。

第一版实现：

- 原生窗口与全屏模式；主界面保持像素块、少量字母和数字，不依赖 WebEngine。
- B3/S23、四边环绕；左键绘制，右键或 Shift＋左键擦除。
- 八挡演化速度：1/8、1/4、1/2、1、6、12、24、40 代／秒。慢速对齐系统整秒，不补算睡眠期间的演化。
- 256 个可写预设、256 个固定随机种子；预览与加载分离。覆盖时仅归档被替换预设。
- 六套配色、单图标昼夜切换；原生版本昼夜图标用于切换 KDE 明暗配色，独立配色块只改变应用颜色。
- 原生文件选择与保存；兼容网页 .life / .lifebank 数据。
- 当前网格、代数和选项的自动检查点；重启恢复，不增加编辑过程历史。
- CPU、内存读数；系统音量、静音、Wi-Fi 和蓝牙快捷控制。缺少工具、服务或设备时显示不可用，操作失败不伪造成功状态。

**第一版不声称已经实现 Wayland 原生背景层。** 普通全屏窗口不等于真正的壁纸：它会遮住桌面。KWin 背景层、桌面图标、面板及输入交互需另做 LayerShellQt / 原生 Plasma 集成并在真实 KDE 会话验证。先确认原生像素显示、系统控制和可靠恢复，再推进桌面层。

## 2. 技术选型

第一版使用 **Python 3 + PySide6（Qt 6）+ NumPy**。这仍是原生 Qt 应用，不是浏览器套壳。Python 方便快速验证系统接口和存储；NumPy 批量计算网格。KDE 官方也支持使用 PySide 开发应用。

界面使用一个自绘 QWidget，由 QPainter 批量绘制矩形，不创建数万个子控件，也不使用字体抗锯齿。先采用简单、可测的原生绘制路径。若性能分析表明绘制成为瓶颈，后续把同一渲染模型移到 Qt Quick 自定义场景图或 C++；第一版不引入未经验证的 GPU 插件。

后端分层：

| 模块 | 责任 |
| --- | --- |
| model.py | 规则、网格、种子、八位编号、笔刷 |
| formats.py | .life / .lifebank 编解码、CRC、大小限制 |
| storage.py | SQLite 事务、单个检查点、预设和被覆盖版本 |
| system.py | 非阻塞命令、系统状态读取、错误与超时 |
| view.py | 物理像素布局、像素字模、命中区及鼠标操作 |
| app.py | 参数、启动、单实例锁、退出保存 |

## 3. 像素与分辨率契约

Qt 窗口大小通常以逻辑像素表示，不能把它误认为屏幕物理像素。渲染时读取窗口 devicePixelRatio，把物理像素坐标映射回 Qt 绘制坐标；所有方块和命中区边界以整数物理像素定义。

目标分辨率采用 320×180 个基础像素的构图：左 256×180、右 64×180。1920×1080 的基础倍数为 6，2560×1440 为 8。右侧字形可使用基础像素的整数细分尺寸，以增加日期和控制区的分辨率。下方约 6% 保持空白。原生窗口不再把先画好的网页纹理拉伸到屏幕。

非目标尺寸采用最大整数倍的 320×180 构图并居中，余处纯色填充。系统最终合成、远程桌面和 XWayland 仍可能缩放结果；不能承诺绕过合成器的任意缩放。应优先在真实屏幕的原生分辨率、原生 Wayland 或 X11 Qt 平台插件上验证。

## 4. 系统接口与状态

第一版通过固定参数的现有工具接入，不执行来自界面的任意 shell 文本。所有进程通过 Qt QProcess 异步执行，设置超时；后台定期刷新真实状态。

| 功能 | 接口 | 说明 |
| --- | --- | --- |
| CPU / 内存 | /proc/stat、/proc/meminfo | CPU 用相邻两次累计计数之差；不把 load average 当占用率 |
| 音量与静音 | wpctl get-volume / set-volume / set-mute | 操作默认音频输出；限制音量不超过 100% |
| Wi-Fi | nmcli radio wifi；nmcli device status | 只控制无线开关，不修改密码和连接配置 |
| 蓝牙 | bluetoothctl show / power | 只控制默认适配器电源，不删除配对 |
| 明暗配色 | plasma-apply-colorscheme | 从已安装方案中选择标准明暗方案；不是替换 Plasma 全局主题和桌面布局 |

工具不存在、设备不存在、硬件禁用、授权被拒绝、命令超时必须可区分于正常关闭。成功发出命令并不等于系统状态已经改变；命令结束后再次读取状态，最终界面以读回值为准。普通用户会话的授权由 NetworkManager、BlueZ 和系统策略决定，不以 root 运行整个应用。

第一版用工具轮询以减少依赖和快速验证。正式常驻版本可替换为 Qt D-Bus / NetworkManagerQt / BluezQt 等事件订阅，界面无需重写。

## 5. 持久化与休眠

使用用户数据目录下的 SQLite 数据库，不把数据写进安装目录；用户可通过 --data-dir 指定独立目录。数据库事务只保留一个最新检查点，检查点含网格、代数、运行状态和设置，校验后恢复。每 10 秒、结束绘制、暂停和正常退出时保存；突然崩溃可能损失最近约 10 秒，不能宣称零丢失。数据库写入失败须在界面和日志反馈。

预设与检查点分开：自动保存运行现场不会覆盖用户预设，也不生成被替换预设备份。只有显式覆盖不同内容的已存在预设才归档旧版本。相同图形重复保存不归档。导入整个库须先完整验证，再用一个事务合并；不能验证一半就修改一半。

休眠期间冻结，不补算。用单调时钟检测大幅时间间隔，恢复后重置调度基准；低速仍在下一个对应整秒演化。界面重新创建、窗口最小化、应用退出与系统睡眠是不同事件，不能把它们混为“休眠”。

## 6. 验证与交付

先运行纯逻辑测试：生命规则、环绕、种子重现、文件与网页的互通、坏文件拒绝、预设覆盖、事务回滚、检查点恢复、慢速时序、坐标和系统状态解析。使用 Qt offscreen 启动并输出两个目标分辨率的原生渲染图；检查像素边界和控制区布局。

当前开发环境不是用户的 KDE 桌面，没有真实音频、NetworkManager、BlueZ 和 KWin 会话。这里能验证命令参数、解析、超时与失败路径，不能把它等同于用户设备上的控制成功。手册明确列出需要 Kubuntu 实测的项目。

第一阶段：原生窗口完整交互和持久化、系统控制接线。
第二阶段：Kubuntu 实测 DPI、音量、无线与蓝牙权限、休眠恢复。
第三阶段：真正的背景层与多屏、自启动、安装包、事件订阅和性能优化。
