# 生命场原生桌面应用：方案与边界

## 1. 目标与第一版范围

在 Kubuntu / KDE 上，将生命场、日期时间、运行代数和常用系统控制集成为一个原生应用，避免网页壁纸宿主额外缩放与销毁网页造成的问题。网页版本继续保留，本实验放在同仓库 native/，不替换在线版。

仅以 **1920×1080、2560×1440 物理像素**为目标。生命场为 256×180、占左侧 80%；细胞分别为 6×6、8×8 物理像素。其余宽度作为右侧控制区。其他尺寸只提供居中的整数倍预览，不承诺铺满。

第一版实现：

- 原生窗口与全屏模式；主界面保持像素块、少量字母和数字，不依赖 WebEngine。
- B3/S23、四边环绕；左键绘制，右键或 Shift＋左键擦除。
- 八挡演化速度：1/8、1/4、1/2、1、2、4、8、16 代／秒，连续填充条不显示每挡下方数字。慢速对齐系统整秒，不补算睡眠期间的演化。
- 256 个可写预设、256 个固定随机种子；预览与加载分离。覆盖时仅归档被替换预设。
- 六套配色、单图标昼夜切换；原生版本昼夜图标用于切换 KDE 明暗配色，独立配色块只改变应用颜色。
- 原生文件选择与保存；兼容网页 .life / .lifebank 数据。
- 当前网格、代数和选项的自动检查点；重启恢复，不增加编辑过程历史。
- CPU、内存读数；系统音量、静音、Wi-Fi 和蓝牙快捷控制，显示已连接 SSID。缺少工具、服务或设备时显示不可用，操作失败不伪造成功状态。

0.3 增加 **Plasma 6 原生 WallpaperItem 插件**，由 Plasma 负责背景层，而非强制窗口置底。Python 后台保留独立模型与 SQLite，插件接收无损物理像素帧并发送结构化鼠标操作。此路径已完成本机传输和 QML 核心交互验证，KDE 特有导入、桌面图标和鼠标路由仍需真实 Plasma 会话验证；不是已经完成全面验收的稳定壁纸产品。

## 2. 技术选型

第一版使用 **Python 3 + PySide6（Qt 6）+ NumPy**。这仍是原生 Qt 应用，不是浏览器套壳。Python 方便快速验证系统接口和存储；NumPy 批量计算网格。KDE 官方也支持使用 PySide 开发应用。

界面使用一个自绘 QWidget，由 QPainter 批量绘制矩形，不创建数万个子控件，也不使用字体抗锯齿。先采用简单、可测的原生绘制路径。若性能分析表明绘制成为瓶颈，后续把同一渲染模型移到 Qt Quick 自定义场景图或 C++；第一版不引入未经验证的 GPU 插件。

后端分层：

| 模块 | 责任 |
| --- | --- |
| model.py | 规则、网格、种子、八位编号、笔刷 |
| formats.py | .life / .lifebank 编解码、CRC、大小限制 |
| storage.py | SQLite 事务、单个检查点、预设和被覆盖版本 |
| system.py | 非阻塞命令、系统状态读取、错误与超时 |
| view.py | 物理像素布局、像素字模、命中区及鼠标操作 |
| app.py | 参数、启动、单实例锁、退出保存 |
| wallpaper.py / plasma-wallpaper | 回环连接、无损帧缓存、Plasma 呈现、托盘与自动启动 |
| ime.py | Fcitx5 与 Rime 状态、真实标点菜单动作、读回 |
| presets.py | 大型确定性场景组合 |

## 3. 像素与分辨率契约

Qt 窗口大小通常以逻辑像素表示，不能把它误认为屏幕物理像素。渲染时读取窗口 devicePixelRatio，把物理像素坐标映射回 Qt 绘制坐标；所有方块和命中区边界以整数物理像素定义。

目标分辨率采用 320×180 个基础像素的构图：左 256×180、右 64×180。1920×1080 的基础倍数为 6，2560×1440 为 8。右侧字形可使用基础像素的整数细分尺寸，以增加日期和控制区的分辨率。下方约 6% 保持空白。原生窗口不再把先画好的网页纹理拉伸到屏幕。

非目标尺寸采用最大整数倍的 320×180 构图并居中，余处纯色填充。系统最终合成、远程桌面和 XWayland 仍可能缩放结果；不能承诺绕过合成器的任意缩放。应优先在真实屏幕的原生分辨率、原生 Wayland 或 X11 Qt 平台插件上验证。

## 4. 系统接口与状态

第一版通过固定参数的现有工具接入，不执行来自界面的任意 shell 文本。所有交互进程通过 Qt QProcess 异步执行，设置超时（只读命令默认 3 秒，蓝牙开关允许 10 秒）；后台定期刷新真实状态。

| 功能 | 接口 | 说明 |
| --- | --- | --- |
| CPU / 内存 | /proc/stat、/proc/meminfo | CPU 用相邻两次累计计数之差；不把 load average 当占用率 |
| 音量与静音 | wpctl get-volume / set-volume / set-mute | 操作默认音频输出；限制音量不超过 100% |
| Wi-Fi | nmcli radio wifi；nmcli device status | 只控制无线开关，不修改密码和连接配置 |
| 蓝牙 | bluetoothctl show / power | 只控制默认适配器电源，不删除配对 |
| 明暗配色 | plasma-apply-colorscheme | 从已安装方案中选择标准明暗方案；不是替换 Plasma 全局主题和桌面布局 |

工具不存在、设备不存在、硬件禁用、授权被拒绝、命令超时必须可区分于正常关闭。成功发出命令并不等于系统状态已经改变；命令结束后再次读取状态，最终界面以读回值为准。普通用户会话的授权由 NetworkManager、BlueZ 和系统策略决定，不以 root 运行整个应用。

第一版用工具轮询以减少依赖和快速验证。正式常驻版本可替换为 Qt D-Bus / NetworkManagerQt / BluezQt 等事件订阅，界面无需重写。

## 5. 持久化与休眠

使用用户数据目录下的 SQLite 数据库，不把数据写进安装目录；用户可通过 --data-dir 指定独立目录。数据库事务只保留一个最新检查点，检查点含网格、代数、运行状态和设置，校验后恢复。每 10 秒、结束绘制、暂停和正常退出时保存；突然崩溃可能损失最近约 10 秒，不能宣称零丢失。数据库写入失败须在界面和日志反馈。

预设与检查点分开：自动保存运行现场不会覆盖用户预设，也不生成被替换预设备份。只有显式覆盖不同内容的已存在预设才归档旧版本。相同图形重复保存不归档。导入整个库须先完整验证，再用一个事务合并；不能验证一半就修改一半。

休眠期间冻结，不补算。同时比较墙钟与单调时钟检测大幅时间间隔（Linux 的单调时钟可能不计挂起时间），恢复后重置调度基准；低速仍在下一个对应整秒演化。界面重新创建、窗口最小化、应用退出与系统睡眠是不同事件，不能把它们混为“休眠”。

## 6. 验证与交付

先运行纯逻辑测试：生命规则、环绕、种子重现、文件与网页的互通、坏文件拒绝、预设覆盖、事务回滚、检查点恢复、慢速时序、坐标和系统状态解析。使用 Qt offscreen 启动并输出两个目标分辨率的原生渲染图；检查像素边界和控制区布局。

当前开发环境不是用户的 KDE 桌面，没有真实音频、NetworkManager、BlueZ 和 KWin 会话。这里能验证命令参数、解析、超时与失败路径，不能把它等同于用户设备上的控制成功。手册明确列出需要 Kubuntu 实测的项目。

第一阶段：原生窗口完整交互和持久化、系统控制接线。
第二阶段：Kubuntu 实测 DPI、音量、无线与蓝牙权限、休眠恢复。
第三阶段：Plasma 壁纸集成已实现实验代码；继续真实桌面验收、事件订阅和性能优化。多屏共用同一模型，按屏幕重建命中区，不提供每屏独立存档。

## 8. 0.2 版本新增

- 蓝牙开启前读取 sysfs rfkill；必要时只执行 `rfkill unblock bluetooth`。硬件禁用或权限不足给出具体错误，不使用 sudo、不重启服务。解析 BlueZ 文本错误并读回 Powered，避免只看进程退出码。
- SSID 从 NetworkManager 缓存的已连接接入点读取，使用 `--rescan no`，不为显示名称不断强制扫描。正确解析 nmcli 转义字段，Unicode 名称在小位图中栅格化后以整数倍像素块显示。
- 文件日志轮换，默认只记录操作、状态变化和失败。详细模式记录有界命令输出；SSID 输出始终省略，MAC 脱敏。只读诊断使用独立轮换文件，避免和正在运行的应用争用同一文件。
- 更新脚本直接下载分支／标签源码快照或指定提交归档，不依赖 GitHub API。优先从 ZIP 注释读取提交号，缺失时用归档内容 SHA-256 标识；验证路径与解压大小，安装到独立版本目录；共享按依赖和 Python 版本区分的环境。新版本 Qt 自检成功后才切换 current；失败保留旧版，保留 previous 支持离线回退。运行数据完全独立，不在升级目录中。

## 9. 0.3 壁纸与输入法的具体边界

- QML 使用 WallpaperItem 原生插件，按屏幕 DPR 请求物理像素。双缓冲 Image 关闭平滑插值，保留上个完整画面，先查询状态版本，有变化才传图。像素来自同一个 QPainter 渲染器；不是网页或 WebEngine。Qt 最终合成仍受桌面缩放影响，不能保证任意分数缩放均无瑕疵。
- 后台只监听 IPv4 回环端口 17832。随机 256 位凭据以 0600 文件保存，安装时写入该用户插件；GET 帧带凭据，其他端点用 Bearer，拒绝非空网页 Origin、跨域预检、任意命令和任意文件访问；正文与分辨率有限制，慢连接超时关闭。不要对外转发。
- 帧缓存只保留最近一张，版本比较含网格、代数、时间、系统状态、残影及页面；不积累图像历史。PNG 使用标准无损 RGB 与快速压缩，避免默认自适应滤波的额外开销。高速稠密图案仍有 CPU 与本机传输成本。未来可改共享内存／原生场景图，不应宣称当前已零开销。
- Plasma 重载／锁屏不会销毁后台模型；后台关闭则按检查点恢复。Qt 文件对话框由同一后台在用户桌面显示，控制窗口关闭只隐藏；显式退出或 SIGTERM 会补存检查点。不会自动更换当前桌面的壁纸或无条件添加自启动。
- 壁纸不接收右键，留给 Plasma；左键与 Shift＋左键承担绘制／擦除。图标布局可能先消费事件。提供壁纸上下文菜单和托盘中的控制窗口作为可操作入口；桌面图标与小部件是否完全兼容需实测。
- 输入法仅调用 Fcitx5 会话 D-Bus，Rime 中／英用 IsAsciiMode／SetAsciiMode，英文键盘激活中文后还需确认 Rime 是否仍处于内部英文模式。标点不是 Controller1 的标准属性，使用 Fcitx notificationitem 的真实 DBusMenu 动作；只接受可识别标点图标或明确的中／英标点标签对。找不到、多个候选或语义不清即不可用。
- Fcitx 的最近输入上下文和按程序记忆策略决定实际作用对象，不可假设它是全局状态。未修改配置、未注入按键、未读取输入文本，也不维护快捷键。

## 10. 0.3.1 修正

- 逻辑呈现尺寸由宿主 Item 决定，Image 锚定整个父项并保持比例。源图用统一缩放系数控制在现有上限，不能把封顶后的源宽高除以 DPR 当作呈现尺寸。输入按当前显示帧的实际宽高、居中偏移与源尺寸换算，兼容切换分辨率期间旧帧仍显示的状态。
- 蓝牙单独使用 500 ms 定时器，Powered 回读后立即读取 Connected 数量；其余系统采样仍为 2 秒。QProcess 按键去重，前一次命令未结束不会堆积；控制操作期间暂停读数，旧轮询不能覆盖新操作结果。没有使用更频繁的扫描或配对查询。
- 设备条使用五个有边框的大格、0–5 数值和超过上限的 +，常态与零连接均可辨认，不再靠几个小像素表示数量。系统读数增强，代数降为次要层级。
- 原有大图案改为均匀对称，向下舰队保持横向镜像、竖直 9 格周期，减少横向列数；不做会破坏飞行器的贴邻排列。新增 020–024 的词典数据独立注明来源和 CC BY-SA 3.0，详见 PATTERNS.md。

## 11. 0.3.2 分数缩放与事件层

用户的 2560×1440、130% 桌面报告逻辑几何 1970×1108。重载 Plasma 后，截图中的面板边界与 7 倍细胞网格加居中留白吻合。接近 16:9 的源图改用标准目标画布，避免逻辑几何取整导致源图少一行而将 min(width//320,height//180) 降一档；其他比例保持既有等比例显示。

Plasma 6.6.6 的 Folder View 在壁纸上方接收空白桌面鼠标，WallpaperItem 内的 MouseArea 可能得不到事件。现在只把透明 MouseArea 的 visual parent 放到同一桌面 QQuickWindow.contentItem；图像不抬高，QObject 仍由壁纸根项拥有。右侧 20% 为控制区，绘制模式才扩大到整个壁纸范围；默认关闭绘制以保留图标和框选。事件用 mapToItem 转回壁纸局部坐标，再映射到当前源帧。右键不接收，壁纸销毁时禁用并移除输入层。

前端在 status 请求中携带版本、逻辑尺寸、父项尺寸、DPR、图像尺寸与绘制状态。后台只保留最近八个不同布局报告，变化时记录日志；提供凭据保护的只读显示诊断端点，不包含凭据或输入文本。按键计数用于检查是否有事件到达。原有输入端点只增加固定 edit 命令，不开放任意执行。

参考 KDE 6.6.6 FolderView.qml、ContainmentItem 的 WallpaperItem z 层与 Qt Item mapToItem API；行为仍需用户实际桌面验证，自动测试中的桌面拦截层不能替代完整 Plasma 会话。


## 12. 0.3.3 状态反馈与活动缩略图

蓝牙将 `pending` 目标与 `state` 已确认硬件状态分开：发起操作前先发 changed，帧修订签名包含 pending；图标立即显示目标，读回成功后清除 pending，失败则清除并回退。连接数量仍依赖实际 Powered／Connected 读数。三枚系统图标使用相同 7×7 像素网格和 28×28 设计尺寸，无独立大块背景，颜色表达状态。

活动预览由 ActivityPreview 原子替换一个 0600 PNG，采用单调时钟限制到 30 秒一次，640×360 等比例缩小。WallPaperItem 在状态响应带来新 URL 时更新自身 `configuration.Image` 并调用 `writeConfig()`；配置增加 KConfig General/Image 字符串。失败保留旧预览，不中断实时壁纸，诊断暴露生成错误。URL 片段变化用于刷新 Qt 图像缓存，实际文件路径固定。KIO 对本地图片按规范路径生成缩略图缓存键；研究依据和限制见 ACTIVITY-PREVIEW.md。


## 13. 0.3.4 图标对比度与常驻输入法

三枚系统图标保留相同无底块网格，关闭颜色由警示色改为当前配色 off；开启仍使用 life。连接数只绘制实际存在的 8×8 方块，0／未知不绘制，未知与超额分别在图标旁标 ?／+，不为电源目标伪造连接数。音量条与图标的几何中心在两个输出尺寸下相差不超过 1 物理像素。

Wi-Fi Unicode 点阵字号从 8／7／6 提高至 10／9／8，保留换行、长名称的字号适应和完整名称提示。输入法紧凑按钮位于顶行空余位置，与绘制模式及 P／I 切换互不重叠；调用现有控制器并共享忙碌和未知状态保护。中／英及 ￥／$ 使用明确点阵字形，不依赖系统中文字体；标点识别语义仍由 Fcitx 的真实动作决定。


## 14. 0.3.5 Rime 货币标签与菜单生命周期

标点候选识别增加 ¥／￥ 和 $／＄，仍要求箭头两侧分别属于明确的中、英文标点标签；隐藏、禁用、多个候选和全角／半角动作不会触发。刷新通过 StatusNotifierItem 的 Menu 属性取得真实菜单路径，先 AboutToShow(0) 再 GetLayout，确保最近输入上下文已绑定。初始化或菜单获取失败清除缓存，下轮重新发现。切换前重新读取动作 ID，发 Event(clicked) 后读回实际状态。

Fcitx 控制器新增有界诊断字典，只包含阶段、菜单条目数、候选数及已确认状态；仅变化时写日志，并在认证的 display-info 内提供。原始菜单和配置不落日志。信息页大号按钮移除 fillRect，字形使用 life／clock／muted 颜色；忙碌提示缩为一个小点，命中区保持不变。


## 15. 0.3.6 倒计时、锁屏与可选服务

Countdown 模型使用单调时钟及运行／手动暂停／完成状态，锁屏为独立的三态条件。仅已确认解锁时扣时，提醒以待消费标记记录，锁屏时延后。SessionLock 用 QtDBus 订阅 ActiveChanged、异步 GetActive 与服务所有者变化，序号使旧查询不能覆盖新信号；异常保持未知，不开放计时。

I 页重排网络读数以加入时间设置区；Qt 对话框配置时长和暂停／取消，生命世界独立运行。倒计时与世界写入同一 SQLite 事务，不保存绝对墙钟截止时间，恢复不扣除离线时段。托盘通知优先，非模态弹窗备用。配色图标的四色采用固定高饱和红蓝绿黄。

新增可选 --install-service，仅显式调用才生成用户单位并关闭旧 XDG 项，默认保持原有自启。生成路径参数按 systemd 转义，保护自定义单位，不自动 daemon-reload 或 enable。英文输入时的标点相关失败仅记日志；即使操作中服务失联，中英状态变未知，也保留发起操作时的静默标记。
